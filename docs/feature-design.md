# PKゲームアプリ 機能設計書

## 0. ドキュメントの位置づけ

本書は、サッカーのPK（ペナルティキック）に特化したモバイル/Webゲームアプリの**機能設計**をまとめたものである。
詳細な技術仕様・画面遷移図・データスキーマの確定に先立ち、「何を作るのか」「どんな体験を提供するのか」を関係者間で合意するためのベースラインとする。

- 対象読者: プランナー / デザイナー / エンジニア
- ステータス: ドラフト（初版）
- 最終更新: 2026-06-23

---

## 1. コンセプト

### 1.1 プロダクトビジョン
> **「スタジアムのPKシーンを、手のひらで。」**

実際のPKの緊張感・スピード感・駆け引きを、キッカーとキーパーの**両方の視点**で体験できるアクションゲーム。
コンマ数秒の判断と読み合いが勝敗を分ける、シンプルだが奥深いゲーム性を目指す。

### 1.2 セールスポイント（差別化要因）
| # | 売り | 実現する機能 |
|---|------|------------|
| 1 | **限りなくリアルなスピード感** | 実測ベースのボール初速・到達時間、可変スローモーション演出 |
| 2 | **圧倒的な臨場感** | 一人称/三人称カメラ、観客歓声・心拍音、スタジアム環境表現 |
| 3 | **攻撃と守備の両体験** | キッカーモードとキーパーモードの完全な作り分け |
| 4 | **読み合いの面白さ** | フェイント・タイミング・コース選択による心理戦 |

### 1.3 ターゲット
- メインターゲット: サッカー好きのライトゲーマー（10〜30代、スマホ中心）
- プレイ時間: 1セッション 3〜5分（スキマ時間でも完結）

## 2. ゲームモード設計

### 2.1 モード一覧
| モード | 概要 | 主な目的 |
|--------|------|---------|
| **チュートリアル** | キッカー/キーパーの基本操作を習得 | 初回オンボーディング |
| **クイックマッチ（vs CPU）** | 5本勝負のPK戦 | 手軽な1人プレイ |
| **アーケード / チャレンジ** | 連続成功数・条件付きステージ | やり込み・スコアアタック |
| **オンライン対戦（PvP）** | 他プレイヤーとのPK戦 | 競技性・継続動機 ※Phase2 |
| **トレーニング** | 自由練習（コース・タイミング確認） | 上達支援 |

### 2.2 PK戦の基本ルール
- 1試合 = 互いに5本ずつ蹴る（同点ならサドンデス）
- プレイヤーは**毎ターン、キッカーとキーパーを交互に担当**（攻守両方を体験）
- 先に得点差が確定した時点で試合終了

## 3. プレイ体験設計（核となる機能）

### 3.1 キッカーモード（攻撃）

#### 操作フロー
1. **コース選択**: 画面上のゴールに対し、狙う位置を指定（タップ or スワイプ）
2. **パワー調整**: ゲージ or スワイプ距離でシュートの強さを決定
3. **タイミング**: 助走中のミートタイミングを合わせる（精度に影響）
4. **フェイント**: 任意でキーパーを揺さぶる動作（ステップ/視線）

#### 操作方式（候補）
- **スワイプ式**: 蹴りたい方向・強さをひと振りで表現（直感的・スピード感重視）
- **タップ＋ゲージ式**: コース指定 → パワー/精度ゲージを止める（精密・読み合い重視）
- ※プロトタイプで両方を試作し、体験の良い方を採用

#### 成否を決めるパラメータ
| パラメータ | 影響 |
|-----------|------|
| コース精度 | 狙った位置とのズレ |
| パワー | ボール速度（速いほど止めにくいが枠を外すリスク増） |
| タイミング | ミート精度。外すとコースがブレる |
| キーパーの予測 | 同じコースを読まれると失敗 |

### 3.2 キーパーモード（守備）

#### 操作フロー
1. **構え**: キッカーのモーション・視線・助走を観察
2. **読み**: コースを予測（左/中央/右 × 上/下）
3. **セービング**: 飛ぶ方向をスワイプ/タップで入力
4. **判定**: 反応速度とコース一致度でセーブ成否を決定

#### 体験のキモ
- ボールは**一瞬で到達**する（リアルな到達時間）。事前の読みが重要
- キッカーのフェイントに釣られると失点
- ジャストタイミングのセーブは派手な演出で報酬感を演出

### 3.3 攻守の非対称性とバランス
- 現実同様、PKは**キッカー有利**が基本（成功率を高めに設定）
- キーパー側は「読み勝ち」の爽快感で報酬を担保
- 連続セーブ・ビッグセーブにボーナススコアを付与してモチベーション維持

## 4. 臨場感・スピード感の演出機能

「限りなくリアル」を実現するための演出系を独立した機能群として設計する。

### 4.1 ボール物理・速度感
- 実測ベースのボール初速（プロのPKは約100〜120km/h）を基準にスケーリング
- キーパー視点ではボール到達まで**0.4〜0.6秒**程度を体感させる
- 軌道はカーブ/無回転など回転による変化を表現（Phase2で拡張）

### 4.2 カメラワーク
| シーン | カメラ |
|--------|-------|
| キッカー | 背後やや上空からの三人称、またはボール一人称 |
| キーパー | ゴール前一人称（飛んでくるボールを正面で受ける） |
| 決定的瞬間 | 可変スローモーション + 自動カット切り替え |
| ゴール/セーブ後 | リプレイ＆歓声カメラ |

### 4.3 サウンド・触覚
- 観客の歓声・どよめき・ブーイング（状況連動）
- 緊張を高める心拍音（蹴る直前に強調）
- インパクト音、ネット/ポストヒット音
- 端末バイブによるキック・セーブのフィードバック（ハプティクス）

### 4.4 ビジュアル
- スタジアム環境（観客、照明、芝、ゴールネットの揺れ）
- 天候/時間帯バリエーション（ナイター、雨 等 ※Phase2）
- スローモーション時の被写界深度・モーションブラー

## 7. システム/技術構成（提案）

> 確定ではなく、設計検討の出発点。

### 7.1 プラットフォーム
- 第一弾: **スマートフォン（iOS / Android）**
- 操作はタッチ前提。横画面を基本とする

### 7.2 技術スタック候補
| 領域 | 候補 | 備考 |
|------|------|------|
| ゲームエンジン | Unity / Godot | 3D表現・物理・モバイル展開のしやすさ |
| 軽量Web版 | Three.js + TypeScript | プロトタイプ/Web配信用の選択肢 |
| バックエンド | Firebase / 自前API | 成績保存・ランキング・PvPマッチング |
| リアルタイム対戦 | WebSocket / 専用サーバ | Phase2で本格設計 |

※ まず**プロトタイプ（コア体験の検証）**を最速で作れる構成を優先する。

### 7.3 オフライン/オンライン
- コア（vs CPU）は**完全オフライン**で成立させる
- オンライン要素（ランキング・PvP）は段階的に追加

## 8. データモデル（概要）

主要エンティティの概略。詳細スキーマは別途定義。

- **Player**: id, name, avatar, rank, rating, 通算成績
- **Match**: id, mode, players, ロケーション, 結果
- **Shot（1キック）**: matchId, kicker, course, power, timing, result(GOAL/SAVE/MISS)
- **Stats**: 決定率, セーブ率, 連勝, ベストレコード
- **Inventory**: 所持アイテム（スパイク/グローブ/ユニフォーム）

## 9. 開発フェーズ計画

## 12. 確定方針（初心者・完成優先版）

> 「初心者がとにかく完成させる」ことを最優先に、下記を確定方針とする。
> 当初の本格3D/mocap路線は将来の理想形として残し、まずは**遊べる完成品**を目指す。

### 12.1 採用技術
| 項目 | 確定 |
|------|------|
| プラットフォーム | Webアプリ（ブラウザ）。インストール不要・共有容易 |
| 言語/ライブラリ | HTML + JavaScript + Three.js（3D描画） |
| ビルド環境 | 不要（ファイルをブラウザで開くだけ。CDN経由でThree.js読込） |
| 配信 | GitHub Pages 等の静的ホスティングで無料公開可能 |

### 12.2 キャラクター生成方針
- **自作モデリング/モーションキャプチャーは行わない**（初心者が最も挫折しやすい工程のため）。
- 段階的アプローチ:
  1. **プロトタイプ**: 球・箱・円柱などの簡易形状でキャラを表現し、コア体験（読み合い・スピード感）を完成させる。
  2. **見た目の差し替え**: 必要に応じて **Mixamo の無料リグ済みキャラ＋アニメーション**（glTF/FBX）に差し替え。モデリング・mocap不要で人型と基本動作が手に入る。
  3. **磨き込み（任意）**: 実プレイ映像から AI/マーカーレスmocap（Move.ai 等）で動きを取得し、リッチ化。
- リグは Mixamo 互換の人型に統一し、後からアニメーションを差し替え可能にしておく。

### 12.3 操作方式（確定）
- **タップ式（コース選択）** を採用。9分割（左右×上中下）のゾーンをタップして狙う/防ぐ。
- 制限時間を設けることで PK の緊張感（スピード感）を演出する。

### 12.4 完成のマイルストーン
1. **M1（達成目標）**: ブラウザで動く、キッカー/キーパー両視点の5本勝負（vs CPU）。← まずここを「完成」とする。
2. **M2**: 演出（歓声・スロー・画面シェイク）と簡易キャラの差し替え。
3. **M3**: スタッツ保存・公開（GitHub Pages）・スマホ最適化。
